# Shared metadata readers (#67)

Every byte reader accepts `&[u8]` and `&Limits`, and returns a typed result.
Callers resolve files with their injected HostEnv before invoking a reader.
No parser performs environment expansion, registry reads, subprocess execution,
include loading, URL opening, or executable lookup.

| Module | Entry point | Result |
| --- | --- | --- |
| text_vdf | parse | Parsed<binary_vdf::Value>, with ignored-include warnings |
| binary_vdf | parse / parse_appinfo | ordered duplicate-preserving Value / AppInfo |
| lnk | parse / parse_with_encoding | Parsed<Shortcut>, including KnownFolder GUIDs |
| url | parse | InternetShortcut |
| desktop | parse | DesktopEntry; localized and argv use explicit context |
| plist | parse | plist::Value |
| protobuf | parse_product_db | handwritten prost ProductDb subset |
| sqlite | Database::open, Database::query | bounded typed rows, sqlite feature |

`Limits` bounds input, each string, nodes and nesting. Recursive readers impose
an additional hard depth ceiling of 128 even if a caller raises its budget.
Appinfo v29's key string table has an aggregate expansion budget so repeated
large keys cannot multiply into unbounded allocations. Unsupported binary field
types fail explicitly; unknown length-delimited Shell Link/protobuf fields are
skipped safely. Invalid UTF-8/UTF-16 is an error rather than a lossy filename.

Shell Links use Windows-1252 for ANSI fields by default. Sources that know the
origin's ACP can inject an encoding_rs encoding, such as Shift-JIS. Known-folder
GUIDs, raw IDLists, relative paths and environment targets remain available for
source-level interpretation. Windows argument parsing does not run a shell.
Desktop Exec field-code replacement happens once and keeps replacement values
inside individual argv elements; missing file/URL selections are removed.
`TryExec` is returned for HostEnv to check, never inspected by the parser.

SQLite is a deliberate bundled-C exception behind a default-on `sqlite` feature.
Source connections use a percent-encoded read-only immutable URI. A database
with a WAL/rollback journal is copied into a private temporary directory, using
bounded copies and before/after file stamps; SQLite recovery and SHM rebuilding
can write only there. A busy/open fallback uses the same snapshot path. The
query API exposes no connection, installs a read-only authorizer, uses bound
parameters and applies row, value, result-byte, VM-step and deadline budgets.
No caller SQL may attach another database, write, or enable extensions.

Golden samples are original synthetic metadata generated by the discovery
fixture builder from reviewable JSON, SQL and text sources. Every reader has
property coverage and a matching libFuzzer target under ../../fuzz.

Format references (no implementation code copied):

- Valve Source SDK `tier1/KeyValues.h` and xPaw/SteamAppInfo's appinfo format README.
- Microsoft MS-SHLLINK specification (LinkInfo, StringData and ExtraData).
- freedesktop.org Desktop Entry specification, especially Exec field codes.
- overtools/TACTLib's original proto_database descriptor, for field numbers only.

The requested freedesktop-desktop-entry 0.8.4 dependency fails to compile on
Windows because it unconditionally imports the Unix-only xdg::BaseDirectories.
Desktop key-file parsing therefore follows the specification directly and uses
the same implementation on all hosts, without copying dependency source.

Libraries are used as ordinary dependencies; their own licenses apply. No GPL
launcher code, comments, test cases or generated source are copied.
